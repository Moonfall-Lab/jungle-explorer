# 27 寸实体地图规格

状态：首版冻结，最终以实际屏幕有效显示区域和小车实测为准。

## 已确认尺寸

| 项目 | 数值 |
| --- | ---: |
| 显示器物理宽度 | 59.6 cm |
| 显示器物理高度 | 33.4 cm |
| 地图逻辑尺寸 | 5 行 × 8 列 |
| 目标格子边长 | 6.68 cm |
| 逻辑棋盘宽度 | 8 × 6.68 = 53.44 cm |
| 逻辑棋盘高度 | 5 × 6.68 = 33.40 cm |
| 左右理论留边 | 各 3.08 cm |
| 上下理论留边 | 0 cm |
| 小车宽度 | 5–6 cm |

地图在横屏显示器中垂直铺满并水平居中：

```text
59.60 cm
┌── 3.08 cm ──┬──────── 53.44 cm / 8 columns ────────┬── 3.08 cm ──┐
│              │                                      │              │
│              │           5 rows × 8 columns         │              │ 33.40 cm
│              │           each cell 6.68 cm          │              │
└──────────────┴──────────────────────────────────────┴──────────────┘
```

## 小车通过余量

格宽 6.68 cm 时：

- 5 cm 宽小车总余量为 1.68 cm，居中时每侧约 0.84 cm；
- 6 cm 宽小车总余量为 0.68 cm，居中时每侧仅约 0.34 cm。

因此 6 cm 车体已经非常接近上限。实体设计必须满足：

- 车轮、外壳、线材和 AprilTag 支架都不能伸出标称宽度；
- 转向必须原地完成，不能用弧线切入相邻格；
- 地图格线应尽量细，不能用凸起边框；
- 车体中心作为定位点，落点应尽量靠近格子中心；
- 每台车分别标定直行和左右转时间；
- 首轮实测应覆盖屏幕中央、四角和边缘，不只测试中心区域。

建议把稳定版车体宽度控制在 5.5 cm 以内，可获得约 0.59 cm/侧的理论余量。

## 全屏显示规则

`apps/web-board` 是实体桌面专用视图。它采用以下布局：

```css
cell = min(viewportWidth / 8, viewportHeight / 5)
boardWidth = cell × 8
boardHeight = cell × 5
```

在确认尺寸的 59.6 × 33.4 cm 屏幕上，高度约束先达到上限，因此每格理论边长为 6.68 cm，棋盘水平居中。

现场必须：

1. 使用横屏方向；
2. 浏览器进入真正全屏，隐藏标签栏、地址栏、收藏栏和系统 Dock；
3. 禁用页面缩放，保持 100%；
4. 打开 `?calibrate=1` 校准视图；
5. 用实体尺测量横向连续 5 格或 8 格，不要只测单格；
6. 如果实测与目标不一致，以有效显示区域实测值更新配置；
7. 完成相机固定 Tag 标定后再开始游戏。

CSS 的 `cm` 物理单位在不同操作系统和显示器上不保证准确，所以不能用网页声明的 `6.68cm` 代替实物测量。

## AprilTag 放置

固定 Tag 应位于棋盘外的左右留边或独立支架上，不得占用 5×8 可落脚区域。四个固定 Tag 必须定义横屏棋盘的四角：

```text
top-left     top-right
    ┌──────────┐
    │ 8 cols   │
    │ 5 rows   │
    └──────────┘
bottom-left  bottom-right
```

固定 Tag 的内边到棋盘边缘距离必须实测并传给定位服务，不能默认等于显示器留边。

## 配置来源

机器可读参数位于 [`configs/hardware/display-27.json`](../configs/hardware/display-27.json)。最后实物尺寸确定后，只修改该配置和 SDK 定位常量，不要在多个服务中分别硬编码。
