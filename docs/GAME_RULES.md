# Jungle Explorer 正式规则书

版本：`1.0`

状态：已冻结

适用范围：软件、实体桌游、主持人流程和演示版本

规则权威：本文件高于早期策划草案、README 摘要和口头说明

## 1. 游戏概述

Jungle Explorer 是一款 2–6 人、约 15–25 分钟的 Human–Agent 协作实体机器人桌游。

玩家是一支深入原始热带雨林的探险小队。玩家不能直接控制探险车，也不能指定坐标、朝向或运动序列；每轮只能通过一张意图卡表达团队策略。Agent 根据已知地图、危险概率、资源价值和团队状态独立选择最终落点，再把路径转换成实体车的运动序列。

游戏的核心不是让 AI 完全服从，而是学习与一个有判断力、会权衡风险的队友协作。

## 2. 两种正式模式

### 2.1 标准模式 `RETURN_TO_BASE`

这是设计效果和设备稳定时使用的完整规则：

1. 找到地图中两个遗迹的任意一个；
2. 取得遗迹后触发 Jungle Awakens；
3. 携带遗迹回到起点 BASE；
4. 回到 BASE 时至少保留 1 HP。

以上条件全部满足才算胜利。

### 2.2 短模式 `RELIC_ONLY`

这是现场演示时间不足或撤离阶段效果不稳定时使用的降级规则：

- 进入地图中任意一个遗迹格并取得遗迹，立即胜利。

短模式不进入 Jungle Awakens，也不要求返回起点。开始一局前必须公开选择模式，中途不得切换。

## 3. 游戏组件

- 5×8 逻辑网格地图一张；
- 带 AprilTag 的探险车一台；
- 顶置或固定全局摄像头一台；
- Game Server、玩家屏幕和 Observer 屏幕；
- 四种共享意图卡各一张：`CAUTIOUS`、`EXPLORE`、`VERIFY`、`FIND_CLUE`；
- 危险、资源、遗迹和地形实体模型；
- 可选 rPPG 摄像头、RGB 灯光和丛林音效。

两台车硬件可以用于轮换或调试，但规则 v1.0 每局只使用一台车。双车同时行动不属于本版规则。

## 4. 地图与开局

### 4.1 地图

- 地图为 5 行 × 8 列，共 40 格。
- 地形可以显示为茂密雨林、沼泽、草地或空地。
- v1.0 的地形只用于视觉和叙事，不单独改变移动速度或伤害。
- BASE 固定在逻辑坐标第 3 行第 1 列。
- BASE 永远安全，不能生成危险或资源。

### 4.2 标准内容配置

每局使用种子随机生成以下隐藏内容：

| 内容 | 数量 | 作用 |
| --- | ---: | --- |
| 危险 | 5 | 进入后损失 1 HP |
| 水源 | 3 | 恢复 1 HP，不超过 3 HP |
| 稀有花朵 | 2 | 立即提供一条正确路径提示 |
| 遗迹标记 | 2 | 无伤公开周围八格的局部地图 |
| 遗迹 | 2 | 取得任意一个即可达成遗迹目标 |

5 个初始危险由以下类型组成：

- 落石区；
- 毒蛇巢穴；
- 断裂藤蔓陷阱；
- 未知丛林事件。

Jungle Awakens 发生后会再增加 2 个动态危险，因此标准模式撤离阶段最多有 7 个危险。

具体分布对玩家保密，只在 Observer Mode 中公开。

### 4.3 初始状态

- 探险车位于 BASE；
- 初始及最大 HP 均为 3；
- 标准时限为 20 分钟；
- 探险车初始朝向由现场摆放决定，并在开始前完成校准；
- BASE 在开局时揭示。

### 4.4 Agent 人格

开始一局时选择一种 Agent 人格。人格只调整 Agent 的决策倾向，不改变地图内容、意图卡规则和胜负条件。

| 人格 | 界面名称 | 决策倾向 |
| --- | --- | --- |
| 谨慎型 `CAUTIOUS` | 守望者 | 尽量避开未知区域，优先选择已知、低风险且便于撤退的路线 |
| 冒险型 `DAREDEVIL` | 开路者 | 偏好高风险路径，愿意以风险换取探索速度和新发现 |
| 资源型 `FORAGER` | 寻迹者 | 优先寻找水源与稀有花朵，并重视沿途资源收益 |
| 直觉型 `INSTINCT` | 逐风者 | 根据附近的局部信息快速决策，及时选择当前更有利的方向 |

## 5. 每轮流程

每轮严格按以下顺序执行：

1. **观察信息**：查看地图、HP、时间、Agent 状态和最近事件；
2. **玩家讨论**：队伍可以自由讨论，但不能向系统输入坐标或方向；
3. **打出一张意图卡**；
4. **Agent 决策**：计算风险、候选落点和路径；
5. **小车行动**：Game Server 输出整数格和 90° 转角组成的运动序列；
6. **最终定位**：小车停车后，由 Rover SDK 返回最终格；
7. **结算最终格**：只处理最终格的危险、资源和提示；
8. **更新地图**：屏幕更新，玩家按提示手动摆放模型；
9. **检查胜负**，然后进入下一轮。

运动过程中经过的格子一律不揭示、不触发危险、不取得资源。对角落点需要实体车通过正交运动到达，但中间格仍不结算。只有 SDK 在运动结束后返回的最终格是规则事实。

## 6. 意图卡

### 6.1 通用规则

- v1.0 使用四张共享、可重复使用的意图卡，不设置手牌、牌库或弃牌堆。
- 每轮只能打出一张。
- 意图卡限制 Agent 的候选范围和策略倾向，但玩家不能指定 Agent 必须选择哪一格。
- 约 40 张实体探险卡的最终配比、消耗和补牌规则留待后续平衡，不属于 v1.0。

### 6.2 `CAUTIOUS` 谨慎推进

- 最终落点只能是当前格周围八格之一；
- 优先选择已知、低风险或可回撤的位置；
- 允许选择对角格。

### 6.3 `EXPLORE` 深入探索

- 最终落点可以位于周围八格或再外侧一层，即与当前格的行列距离均不超过 2；
- 优先扩大视野和信息收益；
- 允许承担中高风险。

### 6.4 `VERIFY` 验证路径

- 最终落点只能是正前、正后、正左、正右四个相邻格之一；
- 用于小范围试探、回溯或验证当前危险约束；
- 不能选择对角格。

这里的前后左右按地图正交方向计算，不代表玩家可以指定具体方向；最终选择仍由 Agent 完成。

### 6.5 `FIND_CLUE` 寻找线索

- 系统提供一条保证正确的线索；
- 取得遗迹前：公布从当前位置通往最近一个未取得遗迹的安全路径上的“下一步安全最终落点”；
- 标准模式取得遗迹后：公布返回 BASE 的安全路径上的“下一步安全最终落点”；
- 不直接公布遗迹的完整坐标或整条路线；
- Agent 将这条线索纳入决策，并输出可执行运动序列。

稀有花朵触发同样形式的正确提示，但不占用下一轮的意图卡。

## 7. 最终格结算

### 7.1 安全格

进入没有危险的格子后，系统必须同时显示：

- 一句自然语言环境描述；
- 周围八格中危险格的准确数量，规则与经典扫雷相同。

数字 `0` 表示周围八格完全没有危险。自然语言可以由 LLM 生成，但数字必须由确定性规则计算。

### 7.2 危险格

- 首次进入危险格损失 1 HP；
- 危险格随后在玩家地图中公开；
- LLM 可以生成具体表现，例如“毒蛇群突然从树冠落下”；
- LLM 只能改变叙事，不能改变固定的 1 点伤害或胜负规则。

### 7.3 水源

- 首次进入恢复 1 HP；
- HP 不能超过 3；
- 使用后消耗。

### 7.4 稀有花朵

- 首次进入立即获得一条与 `FIND_CLUE` 相同格式的正确提示；
- 使用后消耗。

### 7.5 遗迹标记

- 首次进入后，公开该格周围最多八格的地形、危险、资源及扫雷数字；
- 被扫描格不会触发危险或资源效果；
- 只有探险车实际进入某格时才结算该格内容。

### 7.6 遗迹

- 地图中有两个遗迹；
- 第一次进入任意一个遗迹格即取得该遗迹；
- 不要求先收集指定数量的线索或标记；
- 短模式立即胜利；
- 标准模式进入 Jungle Awakens，并开始返回 BASE。

## 8. Jungle Awakens

标准模式取得遗迹后立即触发：

- 游戏进入 `AWAKENED` 阶段；
- 剩余时间按 1.8 倍速度消耗；
- 约三分之一已经探索的安全格重新变为未知；
- 新增 2 个隐藏的未知丛林危险；
- Agent 的主要目标改为携带遗迹返回 BASE；
- 玩家仍必须每轮通过意图卡表达策略。

新危险不能生成在 BASE、探险车当前格、已有危险或已有资源上。

## 9. 遗迹掉落

- 携带遗迹时，如果触发重大未知丛林事件，遗迹可能掉落；
- 遗迹掉落到当前格旁边一个可恢复的安全格；
- 掉落位置必须立即向所有玩家公开，并显示在地图上；
- 玩家必须重新进入该格才能取回遗迹；
- 如果周围没有任何合法掉落格，遗迹不可恢复，游戏立即失败。

普通落石、毒蛇或藤蔓伤害不会令遗迹掉落。

## 10. 胜利与失败

### 10.1 标准模式胜利

同时满足：

- 已取得两个遗迹中的任意一个；
- 携带遗迹回到 BASE；
- 当前 HP 至少为 1；
- 时间尚未归零。

### 10.2 短模式胜利

- 取得两个遗迹中的任意一个时立即胜利。

### 10.3 失败

以下任一情况发生即失败：

- HP 降为 0；
- 20 分钟倒计时归零；
- 遗迹掉落后不存在合法恢复位置。

## 11. Rover SDK 与裁判规则

Game Server 将 Agent 路径转换为：

```text
F2 L F3
```

其中：

- `F<n>`：前进整数格；
- `L`：原地左转 90°；
- `R`：原地右转 90°；
- 不允许曲线或任意角度转向。

Moonfall Rover SDK 完成运动、停车和 AprilTag 最终定位后返回格子、厘米坐标与朝向。规则只采纳最终格：

- 有效且位于地图内：结算该格；
- 定位超时、场外或无有效格子：不结算，主持人重扫或纠错；
- 运动执行结果与计划目标不同：以 SDK 返回的实际最终格为准；
- 同一运动任务不得重复结算。

详细坐标和系统集成契约见 [`ROVER_SDK_INTEGRATION.md`](ROVER_SDK_INTEGRATION.md)。

## 12. rPPG 与 Observer Mode

### 12.1 rPPG

- HR、HRV、紧张度趋势和置信度只作为 Agent 情境输入；
- 不直接增减 HP、时间、危险、资源或胜率；
- 信号质量不足时显示不可用，不得生成假数据；
- 所有结果均为游戏用途，不是医疗测量。

### 12.2 Observer Mode

- 可以显示真实危险、资源、遗迹和 Agent 风险图；
- 玩家在进行游戏时不得查看 Observer Mode；
- Observer 信息不能用于玩家讨论或意图选择。

## 13. 主持人裁决优先级

出现争议时按以下顺序裁决：

1. 本规则书；
2. Game Server 的权威事件日志；
3. Rover SDK 返回的最终格；
4. 主持人的重扫或纠错；
5. 屏幕动画、LLM 文案和实体模型摆放。

屏幕表现或模型位置与 Server 不一致时，以 Server 状态为准并立即修正桌面。
